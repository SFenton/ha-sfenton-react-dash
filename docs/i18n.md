# App copy and localization

User-visible React copy is moving to modular English JSON catalogs under
`src/i18n/locales/`. App Manual content is intentionally outside this
architecture.

## Runtime

- `i18next` and `react-i18next` provide interpolation and plural rules.
- English resources are bundled eagerly. Translation loading performs no
  runtime network request and does not suspend preload renders.
- The initial migrated tranche added about 56 KB of minified JavaScript and
  17 KB gzip across the production bundle (roughly 0.27% of existing gzipped
  JavaScript).
- Application code uses the project facade from `src/i18n/`:
  - `copy(namespace, key, values)` outside React;
  - `useCopy(namespace)` inside React;
  - `copyRef(namespace, key, values)` for declarative configuration.
- Keys are compile-time checked from the imported JSON structure.
- Missing keys throw in development and tests. Production renders
  `[missing:namespace:key]` and logs the key once.

`src/i18n/locales/en.json` contains shared copy. Page, feature, shell, core,
and modal catalogs live in subdirectories under `src/i18n/locales/en/`.
Catalogs use semantic lower-camel keys, named `{{placeholders}}`, and i18next
plural suffixes such as `_one` and `_other`.

## Copy inventory

`scripts/i18n/inventory.ts` scans the runtime import graph from `src/main.tsx`,
catalog leaves, and `index.html`. It structurally excludes:

- `src/manual/**`;
- `src/pages/AppManualPage*`;
- `src/components/manual/**`;
- tests and manual-only metadata;
- runtime backend, recipe, task, and other user-provided values.

The generated inventory is
`scripts/i18n/generated/non-manual-copy-inventory.json`. The companion
`legacy-copy-baseline.json` is a shrinking ratchet: current raw literals must
already exist in that baseline, each record's occurrence count may not
increase, and unrelated removals cannot offset duplicate additions.

Run:

```bash
npm run i18n:sync
npm run i18n:check
npm run test:i18n
```

`i18n:sync` prunes migrated literals from the baseline. It refuses to approve
new raw copy. A scanner-rule change requires the explicit
`tsx scripts/i18n/inventory.ts --refresh-baseline` command and review of the
resulting inventory. The scanner follows local literal constants into visible
JSX/config contexts so indirect labels remain part of the ratchet.

## Boundaries

- Static app labels, states, descriptions, errors, and accessibility names
  belong in catalogs.
- Static location and product names may use a dedicated glossary namespace,
  but the house-style skill must not rewrite household or provider names.
- Live Home Assistant friendly names, task text, recipe content, and other
  backend/user data remain external values and are interpolated rather than
  translated.
- Home Assistant owns mobile-notification delivery and storage. Notification
  copy is represented only in the house-style skill's sanitized reference and
  eval corpus, not in React runtime catalogs.

## Tests and App Manual governance

Tests continue to assert rendered English where wording or accessible names are
the contract. They should not import the same catalog key as the component
under test.

Any source/catalog migration changes the App Manual screenshot fingerprint even
when rendered English is unchanged. Complete the repository's capture,
contact-sheet review, approval, and manual checks before release.
